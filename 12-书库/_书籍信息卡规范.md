# 书籍信息卡规范 · `_book-info.md`

> **适用范围**：`12-书库/《书名》/_book-info.md`
> **关联**：[[12-书库/_说明|12-书库说明]]（入库流程）｜ [[01-索引/采集标准|采集标准]]（素材条目，非本规范范围）

---

## 一、定位与边界

| | 管什么 | 不管什么 |
|---|---|---|
| 本规范 | 书目元数据卡：这本书**是什么**（平台字段 + 本地状态） | 书里的内容、拆解结论 |
| [[01-索引/采集标准\|采集标准]] | 素材条目：一条**能用的东西**（梗／技巧／概念） | 整本书的元数据 |
| [[12-书库/_说明\|12-书库说明]] | 入库流程、目录结构、脚本用法 | 卡片字段定义 |

**一句话**：信息卡是**检索入口与档案**，不写主观判断。学习结论、拆书要点一律另建文件（本书见 [[12-书库/《在异世界末世经营中华餐厅爆火》/简介|拆书任务书]]）。

**豁免**：12-书库为豁免区，信息卡与章节文件都**不登记总索引**、不计入活跃条目口径。

## 二、字段清单

### 必填（12 项）

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | 固定值 | `采集-书籍信息`（与脚本生成值一致，勿改） |
| `status` | 固定值 | 统一填 `待用`——表示"尚未正式拆解使用" |
| `tags` | 数组 | 见第四节标签规则 |
| `title` | 字符串 | **入库书名**，必须与目录名、章节 frontmatter 的 `book` 完全一致 |
| `official_title` | 字符串 | **平台现名**，与平台页一字不差 |
| `author` | 字符串 | 平台署名 |
| `book_id` | 字符串 | 番茄 book_id，**加引号**（防科学计数法／前导零丢失） |
| `platform` | 字符串 | `番茄小说` |
| `creation_status` | 字符串 | 平台状态标签原值：`连载中` / `已完结` |
| `chapter_total` | 整数 | **平台**章节总数 |
| `chapters_on_disk` | 整数 | **本地已入库**章节数（= 目录内章节文件数） |
| `collected` | 日期 | 本次采集日期 `YYYY-MM-DD` |

> `chapter_total` 与 `chapters_on_disk` **必须分列**。两者不等即为缺章信号，一眼能看出来。

### 选填（有则填）

| 字段 | 说明 |
|---|---|
| `author_id` | 平台作者 ID，便于批量拉作者其他作品 |
| `media_id` | 平台作品媒体 ID |
| `categories` | 平台分类与标签数组（顺序照平台） |
| `word_count` | 平台字数，写作 `153.7 万字`（保留一位小数） |
| `read_count` | 平台在读人数（整数，**采集时快照**） |
| `last_chapter` | 平台最新章节标题 |
| `last_publish_time` | 最新更新时间 `YYYY-MM-DD HH:MM` |
| `volume_structure` | 卷结构，如「无分卷（单卷 705 章）」 |
| `cover_url` | 封面直链。**带签名会过期**，仅作当次留痕，不作长期引用 |
| `source` | 采集来源，格式 `番茄小说 - <book_id>` |
| `date` / `updated` | 建档日期 / 最后修订日期 |

入库名与平台名不一致的**必须写清原因**，否则后续检索会撞车。

## 四、标签规则

信息卡标签用**扁平写法**，不加四类标签（题材/类型/状态/格式）——那是素材条目的体系，两套混用会让标签索引打架。

| 序 | 标签 | 说明 |
|---|---|---|
| 1 | `采集` | 固定 |
| 2 | `来源/番茄` | 固定（其他平台替换末段） |
| 3 | 一级分类 | 如 `科幻末世` |
| 4+ | 平台标签 | 逐个照抄，如 `系统` `末世` `美食` `无CP` `群像` |

**不写**：状态类标签（`status` 字段已表达）、自造标签。

## 五、采集 SOP（番茄）

### 5.1 取数命令

```bash
PY="C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe"
SCRIPT="C:/Users/Administrator/.workbuddy/skills/browse-with-opencli/scripts/fanqienovel_site.py"

"$PY" "$SCRIPT" detail <book_id> --chapters 0 > detail.json
```

`--chapters 0` = 拉全量目录（705 章约 95 KB）。只需元数据时可省略该参数（默认 20 章）。

### 5.2 字段映射表

| 平台 JSON key | 信息卡字段 | 转换处理 |
|---|---|---|
| `book_id` | `book_id` | 原样，加引号 |
| `title` | `official_title` | 平台现名（**不是** `title`） |
| `author` | `author` | 原样 |
| `author_id` | `author_id` | 原样 |
| `media_id` | `media_id` | 原样 |
| `abstract` | `## 简介` 正文 | 原文照录，含 `\u3000` 全角空格与换行 |
| `word_count` | `word_count` | 数字 ÷ 10000，保留一位小数 + 「万字」 |
| `read_count` | `read_count` + 快照表 | 原样，标采集时间 |
| `categories[].name` | `categories` + 标签 | 数组第 1 项为一级分类，其余为标签 |
| `category_ids` | 标签 ID 行 | 原样 |
| `chapter_total` | `chapter_total` | 原样 |
| `chapters` | 章节结构分析 | 见 5.3 |
| `last_chapter` | `last_chapter` | 原样 |
| `last_publish_time` | `last_publish_time` | Unix 时间戳 → `datetime.fromtimestamp()` 转本地时间 |
| `creation_status_label` | `creation_status` | **以它为准**（见第六节坑 3） |
| `status_label` | 交叉校验 | 与 `creation_status_label` 冲突时以页面状态标签为准 |
| `cover_url` | `cover_url` | 仅当次留痕，标注会过期 |
| `source` | 采集注记 | `state` = 走 `__INITIAL_STATE__`；`html` = 正则兜底，需复核 |
| `volumes` | `volume_structure` | 长度 1 → 写「无分卷」 |

### 5.3 顺带能算出的结构指标

抓到全量目录后，这些够用且不用读正文：

- **番外切分**：标题含「番外」的章数与起始章号（本书 63 章 / 起于 643）
- **正文终点**：标题含「正文完」的章号
- **标题长度分布**：均值、<8 字与 >15 字的条数
- **标题词频**：食物词、角色词、设定术语词（好书与坏书的差别一眼可见）

示例产出见 [[12-书库/《在异世界末世经营中华餐厅爆火》/简介|本书拆书任务书]] 第一节。

### 5.4 本地侧要数出来的

| 字段 | 怎么取 |
|---|---|
| `title`（入库名） | 读目录名，或读任一章节 frontmatter 的 `book` |
| `chapters_on_disk` | 数目录内章节文件数（排除 `_` 开头的管理文件） |

### 5.5 采集节流

番茄对 `/reader/` 有频率惩罚，`/page/` 详情页宽松但**别并发**。批量采集时串行 + 间隔 ≥1.5 秒，用脚本的 `batch --file ids.txt`。

## 六、已知坑

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | **书名漂移** | 平台改名后，下载器仍用旧名入库，目录名与平台名不一致 | 以平台名为 `official_title`，**入库名不动**（改目录会牵连所有章节 frontmatter）；在 `## 异名说明` 写清 |
| 2 | **字数／章节数过期** | 本地卡是入库那一刻的快照，平台在涨 | 每次采集重取，更新 `word_count` / `chapter_total` / `read_count`；`chapters_on_disk` 不动（除非补章） |
| 3 | **状态字段有陷阱** | `status_code` 恒为 `1`，无判别力 | 用 `creation_status_label`；与 `status_label` 冲突时以页面状态标签为准 |
| 4 | **⚠️ 脚本会覆盖手工补全** | `txt_to_kb.py` 的 `write_book_card()` 用 `'w'` 模式写 `_book-info.md`，**无条件覆盖**。这本书源 TXT 一变、重跑入库，补全的字段全丢 | 见第七节，**未解决前不要重跑入库** |
| 5 | **`cover_url` 会过期** | 链接带 `x-expires` 签名 | 只留痕，不当长期引用 |
| 6 | **目录内 `_book-info-<hash>.md`** | 与 `_book-info.md` 逐字节相同的残留副本 | 历史遗留，确认内容一致后删除（走回收站） |

## 八、存量 19 本补齐 SOP

现状：19 本信息卡都是脚本生成的精简版（6 字段 + `## 简介`）。

| 步 | 动作 |
|---|---|

**节奏**：不必一次跑完 19 本。**先按本规范做满 1 本作为样板**（建议用已拆的这本），确认字段够用、格式顺手，再批量补其余——避免做完全部又改规范。
