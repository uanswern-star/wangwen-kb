# 书库区说明

存放**从番茄等平台下载的原著全文**（采集原文），按「一本一书目」组织、按章节拆分。

## 定位：和 00-收件箱 有什么区别

| 区块 | 存什么 | 特点 |
|------|--------|------|
| `00-收件箱` | 还没整理的零散素材 | 临时、待分拣、会被搬走 |
| **`12-书库`** | **整本原著，按章节拆好的全文** | 长期留存、体量大、作为精读和拆解的底本 |
| `09-归档` | 不再活跃的条目 | 已完结/已用尽/已过期 |

简单说：**收件箱是过路站，书库是长期书房。**

书库里的正文是**别人的作品**，只作为学习和拆解用途，不混入 02-设定 / 04-剧情创意 等原创模块。
从书库提炼出的手法、梗、结构，**另建条目**放到对应模块，并在来源里标注出自哪本书哪一章。

## 目录结构

```text
12-书库/
├── _说明.md                  ← 本文件
├── _书籍ID清单.txt            ← 待处理清单（填书籍 ID，批量导入用）
├── _入库报告.md               ← 每次批量导入的完整性报告
└── 《书名》/
    ├── _book-info.md         ← 书籍信息卡（书名/作者/字数/ID/简介）
    ├── 0001-第一章标题.md
    ├── 0002-第二章标题.md
    └── …
```

章节数超过 200 章时，自动按每 100 章分卷：

```text
《书名》/
├── _book-info.md
├── 001-100/
│   ├── 0001-xxx.md
│   └── …
└── 101-200/
    ├── 0101-xxx.md
    └── …
```

## 条目字段（章节文件）

沿用全库「双轨制」：YAML frontmatter + 正文。

```yaml
---
title: "章节标题"
book: "书名"
author: "作者"
chapter_num: 1
book_id: "番茄书籍ID"
status: 灵感
type: 采集-章节
date: 2026-08-30
tags:
  - #采集
  - #采集/题材标签
  - #来源/番茄
source:
  - 番茄小说 - <book_id>
---
```

## 批量导入流程

1. 用番茄小说下载器把书下载到 `D:\Tools\番茄小说下载器\下载的书籍\`
2. 把书籍 ID 填进 `_书籍ID清单.txt`（一行一个，`#` 开头是注释）
3. 跑批量导入脚本（见下）
4. 看 `_入库报告.md`，检查有没有缺章

```bash
PY="C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe"
"$PY" "D:/网文知识库/.workbuddy/tools/txt_to_kb.py" --batch "D:/网文知识库/12-书库/_书籍ID清单.txt"
```

## 注意事项

- 下载的 TXT 可能**缺章**（SVIP 章节、接口失败），导入后务必看 `_入库报告.md`
- 平台侧可能出现**章节号重复但标题不同**（作者改稿/合章），脚本会标记，不会静默覆盖
- 书库正文体量大，建议按需精读，不要整本丢给 AI 分析
- 用途限定：个人学习拆解，不对外传播、不商用
